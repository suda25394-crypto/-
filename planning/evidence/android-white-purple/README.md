# 白紫版 Android 双独立会话验收

## 范围

本轮使用一台 Android 13（API 33、x86_64）模拟器。Android 用户 11 和 12 分别运行同一安装包，各自保有独立的应用存储、登录态和合成测试账号。测试数据都是人工构造的。产品服务、配对、权限、SQLite 保存和同步均经客户端 HTTP 接口；账号上游、频道上游和模型响应来自本机回环夹具。

## 覆盖安装前

- 两名测试用户安装的旧文件 SHA-256 均为 `6bfa98dd4b3d171428fe1d10137cbe792f2b8a6e469087ed3f76bc757eb9dcde`，包名 `com.coupleai.couple_app`，版本 0.4.0+4。
- 两个系统用户分别强停冷启，旧客户端都恢复了自己的登录态，各自可读共享计划和原有版本。测试预置了共同计划「白紫试用 · 河边散步」与独立心愿「白紫试用 · 去看银杏」，保留原有 SQLite 和设备数据。
- 计划初始版本 2，集合点南门，17:00，双方已对版本 2 表达同意。此基线用于检查覆盖后查看动态能否与同意新版本分开。

### 丢包与回退

在模拟器与本机夹具之间只对两种合成操作各丢弃一次成功响应。服务完整执行了第一次提交，客户端随后执行了用户发起的重试。群消息的共享回复 ID 前缀为 `76ba0795`，账本只增加一次调用。心愿「白紫试用 · 去看银杏」转计划时，重试后仍只有同一条计划；放回心愿、重新排期后计划 ID 保持 `4a012d59…`。A 发布一句话，B 的账号读取到原心愿、该计划和共同回忆的关联，以及该句话。

### 需要持机人完成

本轮无实体手机。所有以上模型回执均标为 fixture。真实 DeepSeek 新增调用 0 次，两次额度保留给两位持机人。请在移动网络、最终 APK 和各自账号下，按交付回执做一次私聊、一次明确 @DP 的群消息，再改集合点并强停重开。普通消息、编辑和查看不需要模型。真实基址、账号和口令不进入本目录。

## 最终文件复验

- A、B 都从「我的 → 登录账号」主动退出，再用各自的合成账号重新登录。两次新登录都直接进入「我们仨」。
- 两位各自强行停止应用并重新打开。两次都恢复本人的会话，群中能看到同一份第 5 版计划，地点为东门；A 的私聊保留，B 的私聊为空。两人可读的心愿、计划与共同回忆仍保留同一条关联。
- 最终文件再次走完 A 私聊（仅 A 能读，fixture 的输入 10／输出 12），以及 A 改第 4 版南门至第 5 版东门、B 从动态查看的操作。B 查看的前后记录分别为 `seen=false → true`，双方的 `choice` 仍为空。两屏设备截图均来自该最终文件，320dp/130% 的检查流程未产生 RenderFlex 溢出或未捕获 Flutter 异常。
