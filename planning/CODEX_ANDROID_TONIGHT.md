# Codex 任务书｜白紫版 Android 双人试用

用户已暂定仓库中的白紫交互稿。请直接接着 PR #1 开发、验证、打包，交付苏打和伴侣各用自己的手机、自己的账号就能登录的 Android 试用版。优先跑通三人群聊、独立私聊和同一份共同计划，再验已有模块。保留两人现有账号与数据。

## 1. 从现有可用版本开始

- 先 `git fetch origin`，检查当前分支、未提交改动和 PR #1 最新提交。Android 开发基线是 `codex/android-dp-d42-d43`，交接时 HEAD 为 `fbd8366`。从包含这份工作的最新兼容提交继续，保留他人新改动。用 `git show origin/main:prototype/white-purple-review/index.html` 读取设计。这里的 [白紫交互稿](../prototype/white-purple-review/index.html) 和 [D-55](../docs/DECISIONS.md) 在 main，原型源码提交为 `5d4d115`。
- 先读开发分支的 `planning/ANDROID_0_4_RECEIPT.md` 和 `deploy/couple/MUSE_0_4.md`。旧 APK 为 `25a08a1`、`0.4.0+4`。[原安装包和校验文件](https://github.com/suda25394-crypto/-/releases/tag/android-dp-v0.4.0-test.4-r2) 可供立即试用。
- 据 Muse 北京时间 11 月 18 日 23:20 的部署报告，公网产品服务已上线 R2（`47f5469`），健康结果为 `schema=3`、`version=0.4.0+4`、`service_revision=2`、`mode=live`。20:45 的真实 DeepSeek 回执来自升级前。优先复用已部署服务和服务端 Key。沿用现有私有配置或让持机人在登录页填写 Muse 报告开头以 `/couple` 结尾的产品基址。健康检查走现有客户端机制。仓库、日志、截图和 APK 里都不要写入双方口令、会话令牌或 DeepSeek Key；真实基址通过私下渠道交付。

## 2. 将白紫交互稿落到真实 Flutter 客户端

1. 保留 `CoupleClient → CloudSession → AppShell` 的登录、会话恢复、版本检查、轮询和请求去重。登录页清楚区分连接服务器与本机演示；正常登录后和恢复会话后都默认打开「我们仨」。云端没有历史时给出空状态。网页样例对话和示例卡片只用于看布局。
2. 首页是我、伴侣和 DP 的真实群聊，直接复用 `CloudChat(shared)`。普通消息只发给双方，显式 `@DP` 才调模型，双方看见同一条回复。右上角打开独立「我和 DP」并复用 `CloudChat(private)`，返回回到原群聊。消息、草稿、收件人、当前上下文按登录身份与会话隔离，切换账号不得带出上一人的内容。允许 DP 正常闲聊、学习、翻译，也能应请求打开已有功能或提出可编辑草稿。
3. 底部固定「聊天／功能／日常／我的」。键盘弹起和进入私聊、二级详情时收起底栏，返回恢复选中页。以原型为准对齐排版、间距和气泡。底色白 `#ffffff`、主紫 `#6939c7`、淡紫 `#f0ebfc`、正文 `#242328`。用简单图标；默认界面不用人物画像。保留在「我的」选择自己的背景照片、预览、应用、取消和恢复默认；照片保留原色，背景随本人保存，不发送给伴侣或 DP。检查小屏、中文大字号、键盘遮挡和系统返回。
4. 「功能」对齐原型 12 个入口。「日常」优先复用 `DailyLifeHome` 和真实约会、日程、心愿、共同记忆。「我的」复用 `CloudProfilesScreen`，保留与 DP 聊天了解自己、修正、确认分享和撤回。私人档案默认仅本人可见。模块内沿用已有 DP 对话入口和授权范围。小宇宙保留独立入口。现有可联网功能接回真实数据，其余入口按实际标注「演示」或「待开放」。先做好本轮主路径，动效留待下一次设计确认。
5. 测一次「心愿 → 计划 → 共同回忆」及修改地点。A 确认修改后，B 从动态进入同一份计划，能看到新地点和版本。B 查看动态不能代替 B 同意。回退、重试和强停再开均不能重复建计划、发送消息或调模型。

## 3. 构建并发布可覆盖安装的 APK

- 沿用应用 ID `com.coupleai.couple_app` 和原测试签名。选择高于现有发布件且未占用的 versionCode（若 5 可用，可用 `0.4.1+5`）。新版客户端要能连接已部署的 `0.4.0+4` 服务。按现有打包流程（`tools/build-test-apk.ps1`）构建。保留原 Release，新增独立测试 Release。
- 执行 `flutter analyze`、现有 Flutter 测试和云端联调夹具；对这次最容易回退的默认群聊、私聊隔离和底栏返回补针对性验证。用两个独立 Android 会话检查收发和计划同步，用模拟上游验证交互、失败重试和零重复调用。复用旧版数据在测试设备上覆盖安装、冷启动并恢复登录。
- 从发布位置重新下载最终 APK，核对 SHA-256、package、versionCode、签名证书与兼容性，并确认下载件正是验证过的白紫版。在 320–390dp 的手机宽度检查首页、右上私聊和共同计划详情，留可公开记录的合成样例截图。私有仓库下载可能要求登录，交付能由苏打下载后直接转给伴侣安装的 APK 文件。

## 4. 联网验收只安排两次真实 DP 调用

优先在最终包、两部手机、移动网络、A/B 各自账号上执行。记录产品健康和测试前后用量。如果已有本版本、同一路径的有效回执，先复用。整个验收最多新增两次真实请求，重跑使用合成上游；维持服务端现有额度。报告中当时的 2/30 是历史快照，跨北京时间午夜时按各自日期核对。用不含私人内容的测试句，勿记录口令、授权头或私聊原文。

| 操作 | 算通过的条件 |
| --- | --- |
| A 在右上私聊问「请用一句话解释水为什么会结冰。」 | A 得到自然回复及成功回执，能读到模型、输入/输出 token；B 的账号看不到此消息和回复。 |
| B 在「我们仨」先发「联调准备好了」，再发「@DP 一天有几个小时？」 | 普通消息双方可见、零模型调用；后一条仅调用一次，A、B 看到同一条 DP 回复。 |
| A 将已有共同计划的集合点从「南门」改到「东门」并确认；B 点开动态；双方强停重开 | B 看到同一计划的最新地点；已读与同意分开。重开恢复各自身份、私聊隔离与计划版本。这一步不需要调用 DP。 |

若拿不到两台实体手机或其私有登录信息，先完成开发、发布和所有可做的独立会话验证，交出安装包，把上述两次真实调用留给持机人。将「两部真机待验」写明确；真实服务异常时保留独立错误信息或请求编号，在已授权范围定位原因，避免反复试扣。只在确需运维处理时提供给 Muse 的具体故障证据。

## 5. 发给苏打的回执

第一行给**新版 APK 下载入口**，写明版本、SHA-256 和仓库提交。接着用手机用户看得懂的三步写清「下载安装 → 填产品基址、各自登录 → 在我们仨和右上私聊试用」。最后分别写出白紫版打包、模拟器双账号、公网服务、真实私聊与群聊、两部实体手机各自的实测结果。每项写「通过」或「待验」并附对应证据。提交实现和脱敏回执到开发分支并更新 PR #1。若还有持机人必须完成的操作，合并为一张短清单。用户要收到能装的软件，不要在交付前停在计划或截图。
