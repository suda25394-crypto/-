# V0.4 手机抽卡选稿｜五套可交互设计样本

> **状态：交互原型已生成并核验部分行为，用户尚未验收。** 仅为手机端设计实验，不意味着最终产品确定用网页承载。

## 改版原因：用户对 V0.3 的明确批评
- “小智”的 UI 控件太多、字还是太多。
- **AI 是整个生态的绝对核心**：用户主要只与 AI 沟通，AI 用授权信息自适应管理和驱动功能模块。
- 功能卡片主要用于**展示简洁结果与进入详情**，不能由用户逐个填表来启动功能。
- **本轮只做手机端样本，不做电脑版样本**。这不是决定最终产品一定是手机原生 App。
- 以后可以**抽卡筛选多套 UI**，收藏每轮喜欢的设计元素，逐步组合；不必一次押注唯一设计。

## 体验方式
直接在手机浏览器打开 [index.html](index.html) 的本地文件；没有依赖，没有 API Key。

设计卡池：
1. 月光玻璃：柔光、紫粉
2. 双人周刊：纸页、杂志
3. 蜜桃气泡：轻甜、圆润
4. 云端晴日：雾蓝、留白
5. 静谧手记：奶油、极简

点「再抽一张」随机抽取，本轮五张不重复；「喜欢这张」收藏；右上角查看收藏并复制偏好。

每张设计都支持：单一 AI 对话入口（本地模拟）、AI 选择的两张展示卡片、点击查看详情、查看我们的小档案。可以输入“我不喜欢人多”，再说“周末想约会”，观察推荐按已知偏好调整。还可说“我喜欢咖啡”或“清除偏好”。

## 真正实现与边界
- 有五套不同的**手机端 UI 布局、配色和交互方案**；没有单独设计桌面版布局。
- 抽卡、去重、收藏、展示详情、关键词驱动推荐、偏好变化均以原生 JavaScript 实现。
- **所有 AI 行为均是本地规则模拟**，没有接入 DeepSeek、真实长期记忆、双人账号和云端联动。
- 本地浏览器尝试使用 `localStorage` 保存评选收藏及模拟偏好；跨刷新持久化尚未在浏览器自动化环境完成完整端到端验证。
- 2026-11-16 用 Playwright/Chromium 的 **390×844、360×740** 手机视口验证抽卡、聊天、偏好影响建议、卡片详情和收藏，未发现 JS pageerror 或页面横向滚动。
- **用户尚未选择喜欢的方案，不把任何一套当作定稿。**
