# 双生宇宙：AI 情侣超级 App｜产品草稿 V0.1

**状态**：创意原型，不是最终方案。名字“ 双生宇宙 ”为暂定工作名。

## 1. 一句话定位
不是塞了 AI 聊天框的情侣工具箱，而是一个**AI 先认识情侣、让共同经历塑造小宇宙、把愿望变成现实行动**的双人生活空间。

## 2. 当前确定的方向
- 面向情侣，不局限于某项功能；最终可扩展为一个整合生活、娱乐、记录、关系沟通的超级 App。
- 以 AI 作为核心协调者，而不是单独添加一个问答页面。
- 首次进入要有“哇，原来还能这样”的感受：根据情侣信息出现独有的**小宇宙、角色、故事或虚拟空间**。
- 核心超能力先聚焦两种：**A. 创造世界**；**B. 把愿望转化为现实行动**。以后再扩展更多能力。
- 功能可借鉴全球成熟产品的通用思路、交互机制，但品牌、视觉设计、素材与具体表达自主设计。
- 项目预算敏感，优先复用 DSH、Codex，避免新付费服务和无止境开发。
- 不陷入单项功能无限讨论；先做出草稿和能运行的版本，再根据真实体验迭代。

## 3. 目标人群与问题假设
- 目标人群：愿意双人尝鲜、分享回忆或规划生活的情侣。
- 现有工具的痛点假设：功能分散、缺乏连续新鲜感、只在纪念日或争吵时使用、缺乏双人共同创造感。
- 尚未验证：用户是否持续使用虚拟世界，以及愿不愿意为持续的 AI 个性化付费。

## 4. 核心体验闭环

输入少量情侣线索 → 产生专属小宇宙 → 通过回忆/愿望令世界生长 → AI 提供新灵感/可执行计划 → 现实中产生经历 → 回到世界记录 → 下一轮变化。

### 黄金开场（避免问卷劝退）
1. 视觉：打开看到尚未诞生的小宇宙，只有一个“开启我们的宇宙”按钮。
2. 轻引导：两个称呼、一句共同回忆、一个可选心愿、几枚偏好标签。无需注册，可稍后编辑。
3. 即时反馈：出现与回忆相关的星球；用户能打开双人故事，并将回忆或心愿立即保存。
4. 看到“这 App 能做什么”：个性化卡片引导进入“回忆变星球 / 心愿变计划 / 今日灵感”。

## 6. 技术思路：省钱优先
- **当前原型**：一个 `index.html`，HTML + CSS + 原生 JavaScript；无服务器、无依赖、无账户、无 API 成本。移动端优先。
- **当前“AI”是规则模拟**，并没有调用 DeepSeek；目的是低成本验证首次体验和功能闭环，不能宣称是真实 AI。
- **下一阶段真实 AI**：前端发送用户意图到服务端 → 服务端通过 DeepSeek API 产生**受约束 JSON 指令** → 业务逻辑验证 JSON → 客户端调用预制页面/场景/道具 → 保存经过用户同意的记忆。
- **禁止把 DeepSeek API Key 放进网页前端**；必须通过服务端代理并设置限额、限频、缓存、失败回退。
- “AI 创造世界”初期不做实时生成 3D 模型：优先预制 2.5D 场景、样式和动画，AI 只控制哪些元素出现。
- 正式产品必须设计两个人的权限边界：自己私有、双方共享、单次授权；不能默认共享一方与 AI 的私人内容。

## 7. 商业模式草案（待验证）
- **免费**：完整可体验的基础双人空间、回忆、部分灵感、心愿和计划。
- **会员**：进阶 AI 创作、更多世界主题、复杂联动、深度定制和更高调用额度。
- 不预设价格，不承诺收益；先看用户能否完成开场、是否愿意二次进入、哪些功能被重复使用，再决定付费墙。

## 8. 三个主要风险
1. **一眼惊艳，但三天后无聊**：重点验证持续生长机制，而不是堆一次性动画。
2. **表单太长，用户没耐心**：首次输入控制到极少信息，优先即时反馈。
3. **技术成本和复杂度失控**：用有限预制素材和规则模拟验证体验后，再按数据引入真实模型与双人实时联动。

## 9. V0.1 原型验收方式
- 手机浏览器打开，无需账号、安装和付款。
- 60 秒内能输入信息、看到个人星球（是设计目标，不是实测结果）。
- 能新增回忆，并看到世界回忆数变化；能新增心愿、查看计划并标记完成。
- 页面刷新后，已有资料仍在同一个浏览器里。
- 各按钮不是虚设：未实现的功能要明示状态，不假装调用了 AI。

## 10. 下一步只做一件事
真实体验 V0.1，判断最核心的“第一次进入是否有惊艳感”是否成立。下一次再选择**只改最影响体验的一处**，避免无限扩展。
