# V0.5｜真正不同的五种手机端交互方案

> 状态：**已编写、已做 Chromium 主流程测试；尚未经用户视觉验收。** 这是 UI 探索的单文件交互样本，不代表产品已经选定其中某一种，也不代表已经接入真正 AI。

## 改版依据
用户指出 V0.4 “换汤不换药，基本都一个格式”，仅仅改配色、圆角、字体不足以称为多方案。V0.5 **要求不同的信息架构与不同的主要操作动线**，而不是同一个卡片列表的五种主题皮肤。

## 5 套真正不同的结构

| 编号 | 方案 | 首页结构 | 主要操作 |
|---|---|---|---|
| 01 | 对话流 | **聊天就是首页**；功能结果镶嵌在对话气泡里 | 底部单一输入 |
| 02 | 沉浸画布 | **大幅抽象画面 + 浮动结果**，大面积留白 | 底部呼出 AI |
| 03 | 环形中枢 | **AI 位于中央、功能为环绕节点**，没有传统卡片列表 | 点中央 AI，节点展示详情 |
| 04 | 双人分屏 | **两人各占一半**，AI 在中间连接、协同 | AI 桥接并建议共同方案 |
| 05 | 杂志叙事 | **大标题、编辑式画面与单条内容线索** | 底部 AI 入口，点标题展开详情 |

每一套采用独立 DOM 版式和 CSS 布局，抽卡评估栏是**样本测试工具**，不属于正式产品 UI。

## 用户已经确认的设计原则
- AI 是整个生态的主交互中枢，日常需求通过一个主要 AI 入口提出。
- 功能模块主要展示 AI 调用后的结果，复杂信息点开详情，不要求用户在每个模块重新输入。
- 手机优先，降低字数、按钮数量、滚动和首屏信息负担。
- 抽卡逐一比较，收藏喜欢的部分；**不要因一次选择就擅自确定全局视觉方向**。

## 能运行的演示与限制
- 单文件 `index.html`，原生 JS，无构建依赖；允许收藏设计、五张不重复抽取、查看详情、模拟对话和偏好修正。
- 已用 Python Playwright + Chromium **390×844** 视口，采用 `page.set_content` 渲染 HTML 测试五套切换、抽卡不重复、收藏、AI 对话、记住“我不喜欢人多”并影响下一次约会建议、详情与方案收藏，**无 JS pageerror，未发现横向溢出**。
- 受测试环境限制，`file://` 打开文件受管理员策略阻止；**不能声称测试了真实手机或跨刷新本地保存**。
- 所有“AI”都是本地关键词和固定规则模拟，没有真实 DeepSeek、双人账号、实时信息、持续关系记忆服务或授权共享系统。双人分屏状态仅是 UI 占位示例。
- 产品最终载体仍未确定，本轮仅限手机 UI 选稿。

历史 V0.1~V0.4 保留，不覆盖。
