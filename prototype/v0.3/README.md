> 开发前请先阅读 [产品总纲](../../docs/PROJECT.md)、[AI 核心](../../docs/AI_CORE.md)、[已确认决策](../../docs/DECISIONS.md)。

## 为什么重做

用户对 V0.2 的明确反馈：仅「我们的小档案」配色、卡片视觉获得认可；其他页面文字过多、信息密集、滚动过长、不高级、缺少渐进披露。尤其反对把“用户自己填写每个功能”作为主交互：**用户的需求全部通过一个主要 AI 入口表达，由 AI 自适应理解并编排功能；模块卡片负责展示与进入结果，而不是分别要求用户填表。**

## V0.3 交互结构

- **唯一主交互路径**：全局 AI 输入框 → 对话面板 → AI（规则模拟）选择功能组合 → 结果卡片 → 点开详细方案。
- **首页减负**：少量关键内容、AI 主入口、可被动态推荐的展示卡片。完整功能在「发现」，较长的解释只在详情出现。
- **我们的档案**：延续淡紫、柔粉视觉；偏好在对话中更新，在「我们」页面可删除。
- **体验进化示例**：先对 AI 说“我不喜欢人多”，再说“周末想约会”，下一次建议会参考该偏好。
- **独立模块**：约会、惊喜、沟通、回忆、心愿、餐食、日程和小宇宙并列；宇宙不是产品主体。
- **收藏**：从方案详情收藏，可在「我们 → 收藏的计划」查看或移除。

## 运行
现代浏览器直接打开 `index.html` 即可。无需依赖、账号或 API Key。所有演示数据默认来自**假数据**；请不要输入真实私密信息。

## 真实能力边界
当前“AI”使用关键词、模板和本地 JavaScript 来模拟路由、记忆及多模块联动；**未接入 DeepSeek、没有模型推理、没有真实持续关系记忆服务、没有双人账户或云同步、没有实时外部数据或自动行动**。浏览器本机 `localStorage` 由代码读写；是否跨刷新正常存储仍需在实际打开文件后验收。
