# AI 与技术思路｜节约成本优先

## 当前资源与边界
- 可使用工具：**DSH（DeepSeek Harness）与 Codex**；优先复用已拥有的能力和现有项目。
- 不把“探索一种新技术”理解为已经决定迁移架构。
- 没有专门开发团队；优先少依赖、少后端、低维护。
- 用户曾提出未来考虑用 **DeepSeek API** 控制推理成本；目前模型接入只是假设，尚未开发。

## 现有 V0.1 原型（已检查文件）
历史会话生成过 `index.html` 单页原型与 `产品大纲_V0.1.md`。
当前原型采用 HTML/CSS/原生 JavaScript：
- 无真实 API、无账号、无远程数据库；
- 用关键词与模板模拟“AI 推荐/创作”，并有显式说明；
- 使用浏览器 `localStorage` 保存基本资料、回忆、心愿（清缓存会丢失）；
- 适合本地体验，不适合储存私密聊天和敏感信息。

截至 2026-11-16：已核实本地文件存在并阅读主要代码与大纲，**不能等同于完整跨设备/浏览器端到端测试**。源代码是否已经同步此仓库以仓库文件为准。

## 真正接入 AI 时的建议链路（未实现）
```text
用户意图（网页/小程序）
   ↓
业务服务端（身份校验、权限、速率/预算限制）
   ↓
DeepSeek API（结构化 JSON，不直接执行任意代码）
   ↓
输出校验（允许的动作、字段、长度、花费）
   ↓
调用预制功能和场景（首页模块/小宇宙/计划）
   ↓
保存用户授权的结果（个人/共享分区）
```

### 降低成本和故障
- 不把 API Key 放进客户端代码。
- **AI 作决策，前端做渲染**：优先预制 2.5D 场景、角色与动画资源，模型输出“选哪个场景、改什么参数”，而不是每次生成 3D 世界。
- 尽可能使用缓存、模板、短上下文摘要、异步低优先级任务、回退规则。
- 双方每人有独立隐私区；共享内容明确需要授权。
- 对异常与滥用设置调用上限/频率限制/预算报警，不让“一张图片”消耗失控。
- AI 在感情沟通方面应辅助表达和复盘，不能装作全知法官。
