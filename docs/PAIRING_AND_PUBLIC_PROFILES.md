# 配对、公开个人档案、双 AI 聊天口与三人群聊｜V1.0 需求整理

**记录日期：2026-11-16。** 本文件是原有「私人空间与权限分层」草案经用户纠正后的**新现行设计依据**，而非已实现成果。

## 一、用户明确决定（A）

1. **先配对**：两人登录后形成一个情侣空间，使用**同一套 DeepSeek/AI 中枢**和功能生态。
2. **取消之前独立的“私人空间”功能体系**：不再设计两套私人功能库、私人/共同记忆三档权限大系统。
3. **保留双方各自一个独立的 AI 聊天口**，各自直接与同一个 AI 中枢交流。聊天口是交互入口，不代表要新增复杂“私人空间”模块。
4. **共同空间不变**：你 + 她 + AI 三人群聊；双方在共同空间内都能查看对方在这里发布的消息，也可以共同向 AI 提问。
5. **个人档案**按 D-45 由两人各自与 DP 在自然对话中建立，依据本人确认的资料生成可互看的图文档案。
6. **两人的个人档案与画像信息公开互看**，也可在三人共同空间向 AI 询问相关信息。
7. AI 依这些资料、双方使用过程的反馈与实时需求个性化安排已有模块。小宇宙只是并列模块之一，AI 仍是生态核心。

## 二、建议的最简模型（C，尚未确认细节）

```
    你（用户 A） ───── 配对 ───── 她（用户 B）
         │                           │
      与 DP 聊天                   与 DP 聊天
         └──── 两份公开档案 ────────┘
                       │
                 一个 AI 中枢
           ┌───────────┼───────────┐
       我的 AI 聊天   她的 AI 聊天   三人共同群聊
           └───────────┼───────────┘
                AI 管理功能生态
          约会 / 心愿 / 回忆 / 小宇宙 ...
```

- **公开的是两份已经填好、本人确认发布的档案**，不是把两个聊天口的全部消息自动同步。
- **建议**个人聊天消息默认只展示在发送者自己的聊天口；需要双方同时看到的内容进入共同群聊。这保留聊天体验的边界，不等于恢复旧「私人空间」多层架构。
- **建议**聊天中出现新偏好时，AI 提议「把这条加入我公开的档案吗？」得到本人确认后再写入。编辑或删除个人档案也应由档案主人控制。
- **建议**公开档案可由本人修改，AI 可建议修订，但不能因一句临时谈话擅自更新为双方事实。
- **建议**人格画像主要描述相处风格、沟通习惯、偏好决策方式，避免固定人格标签或伪装成临床测评；可自行纠正和更新。
- **建议**AI 在共同群聊回答「他喜欢什么」时引用对方**已确认公开档案**；不能把对方仅在单独聊天里说过、尚未发布的消息当成公开事实。
- 建档、公开、纠正与删除按[对话建档规范](PROFILE_QUESTIONNAIRE_FINAL_V1.md)执行。

## 三、与旧草案的关系

此前 [PRIVACY_AND_SPACES_DRAFT.md](PRIVACY_AND_SPACES_DRAFT.md) 提出的「两个独立私人功能空间 + 共同空间」「个人/用于共同推荐/双方共享三级记忆许可」**不是现行需求**。该文件保留历史记录但已被本文件取代。

**最小权限边界仍然需要代码落实**：登录用户身份、本人档案编辑权、两人公开档案可读、单独聊天消息不自动公开、共同群聊同步和配对关系校验。无需再设计层层弹窗与复杂隐私分级。
