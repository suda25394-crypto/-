# 功能地图｜AI 主导的情侣生态

更新：2026-11-16。**小宇宙只是一个重要核心模块，其他功能不从属于它。**

状态：✅ 方向已确认 ｜ 🧪 原型中有本地模拟/占位 ｜ ⏳ 未实现 ｜ 💡 探索功能。**功能被用户喜欢不等于代码已实现。**

## 使用越久越贴切：贯穿所有模块的循环

**首次画像不是产品的终点，而是起点。** 当前的关系记忆/实时情境与用户明确反馈共同影响功能导演的下一次决策；用户随时可以纠正喜好、撤回授权或手动打开其他模块。建议的留存机制不能只是“历史记录越存越多”，必须在下一次真实功能使用中体现改善。

## 第一层：AI 智能中枢（产品真正核心）

| AI 能力 | 作用 | 当前状态 |
|---|---|---|
| **关系记忆** | 记住双方主动授权的偏好、习惯、共同经历，允许纠错、更改、删除 | ⏳ 未实现真正可控的长期关系记忆 |
| **功能导演** | 根据用户实时意图动态选择/组合/排序各类模块，完成跨功能任务 | 🧪 仅有本地偏好驱动的卡片排序；真正调度未实现 |
| **秘密策划师** | 根据情境与授权信息生成惊喜、互动方案、活动提醒 | 🧪 仅有模板灵感，真正策划和执行未实现 |
| **关系守护者** | 日常理解、表达帮助、争执后的自愿沟通复盘 | 🧪 原型仅占位，不是实际调解产品 |
| **AI 首次引导与动态首页** | 通过轻交互认识个人及情侣偏好，日后根据情境不断变化 | 🧪 本地表单和标签模拟；没有真实 AI |

这四种能力是**同一智能中枢的职责分工**，不是已实现的四名独立 Agent。

## 第二层：可独立运行、又可联动的功能模块

| 功能领域 | 具体模块 | 当前状态 | 与 AI 联动举例 |
|---|---|---|---|
| **生活/协作** | 约会规划、共同日程、吃什么/看什么、购物与出行清单 | ⏳ | 一句“周末想玩” → 计划 + 清单 |
| **共同心愿** | 心愿清单、可行性步骤、共同目标、预算协作 | 🧪 心愿+三步模板 | 用户说想实现某事，导演联动行动模块 |
| **情感/沟通** | 心情记录、沟通练习、表达翻译、争执后复盘 | 🧪 占位 | 守护者在用户主动选择后协助 |
| **记忆/内容** | 相册、情侣故事、纪念日、回忆整理 | 🧪 回忆输入与模板故事 | 记忆提供授权素材，AI 产出故事 |
| **惊喜/礼物** | 惊喜计划、礼物推荐、个性化活动 | ⏳ | 策划师根据自愿提供的偏好设计惊喜 |
| **趣味/互动** | 默契测试、小问卷、游戏、双人挑战 | 💡 | 动态生成适合两人的题目或活动 |
| **创意视觉** | **专属小宇宙、角色、剧情、虚拟空间** | 🧪 主题星球演示；角色/动态世界未实现 | 需要视觉体验时调用此模块 |
| **个人/双人系统** | 账号配对、私人/共享区域、隐私权限、云端同步 | ⏳ | 为 AI 读取和分享关系信息设边界 |
| **商业化** | 免费基础服务、会员进阶能力、额度控制 | ⏳ | 高成本功能按透明规则限额 |

以上不是封闭清单；用户希望未来可增添更多有趣且实用的能力。

## 跨模块联动（核心设计）

**联动 A：不经过小宇宙。**“今晚不知道吃什么” → 关系记忆（口味） → 功能导演 → 菜单/预算/约会安排 → 可收藏计划。

**联动 B：不经过小宇宙。**“她生日快到了” → 策划师 → 喜好（合法授权）+ 礼物清单 + 预算 → 惊喜计划。

**联动 C：可以调用小宇宙。**“把我们的第一次见面留住” → 回忆 + 故事 + 视觉小宇宙（可选），以后仍可由角色/场景延伸新内容。

**联动 D：关系支持。**“我们最近总是误解彼此” → 守护者 → 双方自愿输入 → 沟通建议 + 复盘模板，不能未经授权给另一方发送信息。

**AI 的作用是当下决定什么组合最适合，而不是每次都固定按 A→B→C 顺序执行。**

## 开发原则

- 不把“宇宙生长”当作所有功能唯一的数据结构。
- 用户可以自己直接打开模块，AI 可推荐，但不应垄断所有入口。
- AI 的决定要可解释、可取消、可纠正、尊重隐私；不能毫无规则地改 UI 或执行危险/昂贵操作。
- 功能数可持续增长，**每版开发任务保持少量可验收的纵向流程**。
